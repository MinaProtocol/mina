Rosetta `/search/transactions` searches by account no longer scan every user command. The archive migration (`src/app/archive/upgrade.sql`) indexes `user_commands.fee_payer_id`, `source_id` and `receiver_id`, and the user-commands search query uses them; that query also no longer copies every canonical block per request. On a running archive the indexes can be built beforehand with the `CREATE INDEX CONCURRENTLY` statements documented in `upgrade.sql`, after which the migration only checks the catalog.
