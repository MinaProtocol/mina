Report invalid `daemon.json` settings as configuration errors instead of crashing

A setting in the `daemon` section of a configuration file with a value the daemon could not use, such as text where a number was expected or a negative `snark-worker-fee`, made the daemon crash and write a crash report without saying which setting was wrong. The daemon now stops with an error naming the setting, the file and the value. Invalid port, snark-work and gossip-logging settings are also reported earlier, before the genesis ledger is loaded.
