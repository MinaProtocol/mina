Fix the GraphQL `catchupStatus` field to report how many blocks are in each catchup stage

`catchupStatus` previously returned only the names of the ledger-catchup
stages, discarding the counts, so it could not tell you how far along catchup
was. It now returns an object with a count per stage — `finished`, `failed`,
`toDownload`, `toInitialValidate`, `toVerify`, `waitForParent`,
`toBuildBreadcrumb` and `root`.

This changes the field's type from a list of strings to an object, so any
query selecting `catchupStatus` needs updating.
