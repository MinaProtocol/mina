Speed up gossip and block application by skipping unread log messages

Nodes were building detailed log messages describing every transaction in a block and every transaction gossiped to a peer, including hashing each one, and then discarding the result because the node was not logging at a verbose enough level to print it.

These messages are now built only when something will actually read them. On a test network carrying a thousand transactions per block, this removed about 9% of the block producer's CPU usage, most of it from broadcasting transactions to peers. Nodes that only apply blocks benefit too, though by less. Log output is unchanged at every level.
