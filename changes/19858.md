Fix archive node skipping blocks that touch an account with a non-UTF-8 token symbol

A token symbol or zkApp URI can contain any bytes. The archive node could not store a value that is not valid UTF-8 (for example a single 0xff byte) and skipped every block that touched such an account, and it silently cut a value at a zero byte. The archive now stores these values byte for byte. Run the archive upgrade script; if your archive ran with `PGCLIENTENCODING=LATIN1` as a workaround, run it with `PGOPTIONS='-c archive.value_encoding=LATIN1'`.
