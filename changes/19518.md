Fix per-network daemon images and automode installs starting without a node profile

The per-network daemon Docker images (`mina-daemon:<version>-<network>`) and automode installs (`mina-<network>-automode`, the auto-hardfork image) did not carry a node profile, so the post-fork node silently ran with development constants. The per-network image is now built on the profiled image, and the automode post-fork package depends on the matching `mina-<profile>-profile` package. `mina-dispatch` now refuses to start a runtime that has no profile, with the error `profile_not_set`.
