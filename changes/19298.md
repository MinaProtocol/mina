Replace mina-missing-blocks-auditor and the missing-blocks guardian script with one app

`mina-missing-blocks-guardian` is now a single executable with the same `audit`,
`single-run` and `daemon` subcommands and the same environment variables, so
existing archive deployments do not need to change.
`mina-missing-blocks-auditor` is no longer installed: run
`mina-missing-blocks-guardian audit --archive-uri URI` in its place, which
prints the same report and uses the same exit-code bits.

The guardian no longer saves a bucket's "not found" page as a block file. A
download that returns 404, is refused, is redirected, or is not a valid block
now stops the run with a message naming the URL and the reason, instead of
failing later with a parse error that named neither. A block the archive
accepts but does not store, and an archive that does not reach back to a
genesis or hard-fork block, are also reported instead of making the guardian
retry the same block forever. The audit no longer fails with a decoding error
on an archive whose earliest block is not the genesis block.

New optional flags let you set the block source, network, poll interval and
retry behaviour on the command line, cap one repair pass with `--max-blocks`,
stop the walk at a fork point with `--min-height`, and check that the missing
blocks can be downloaded without writing anything with `--dry-run`.
