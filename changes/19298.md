Replace mina-missing-blocks-auditor and the missing-blocks guardian script with one app

`mina-missing-blocks-guardian` is now a single executable with the same `audit`,
`single-run` and `daemon` subcommands and the same environment variables, so
existing archive deployments do not need to change.
`mina-missing-blocks-auditor` is no longer installed: run
`mina-missing-blocks-guardian audit --archive-uri URI` in its place, which
prints the same report and uses the same exit-code bits.

The guardian no longer saves a bucket's "not found" page as a block file. A
download that returns 404, is refused, is redirected, or is not a valid block
now stops the run with a message naming the URL and the reason, instead of
failing later with a parse error that named neither. A block the archive
accepts but does not store, and an archive that does not reach back to a
genesis or hard-fork block, are also reported instead of making the guardian
retry the same block forever. The audit no longer fails with a decoding error
on an archive whose earliest block is not the genesis block.

A block the guardian cannot fetch or store no longer hides the rest. It sets
that branch aside, repairs the branches it can, and lists what is still open,
so one unreachable block at the bottom of a truncated archive no longer stops
the gaps above it from being filled. `single-run` exits non-zero whenever a gap
is left.

New optional flags let you set the block source, network, poll interval and
retry behaviour on the command line, cap one repair pass with `--max-blocks`,
and check that the missing blocks can be downloaded without writing anything
with `--dry-run`. Use `--min-height` on an archive that starts at a hard fork
or was restored from a truncated dump: it declares where the chain is meant to
start, so the earliest block counts as the bottom of the archive instead of a
missing block, and `audit` on a healthy archive of that shape returns success.

Every subcommand now exits 0 when there is nothing wrong and 1 when there is.
`mina-missing-blocks-auditor` returned a bit mask that had to be decoded, and
the script's `audit` subcommand always returned 0; both are replaced by a plain
0 or 1, with each problem logged as an error line naming it. A script that
tested particular bits should test the exit status instead. Two cases that the
bit mask missed are now reported: an archive holding no canonical block at all,
and, on an archive that starts at a hard fork, a canonical chain that really is
short — it used to be measured as if every chain began at height 1, so a
healthy forked archive was always reported as incomplete.
