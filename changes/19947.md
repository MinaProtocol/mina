Make the missing blocks guardian stop and report when it cannot restore a block

`mina-missing-blocks-guardian` now checks every setting before it starts. Each wrong or missing flag or environment variable is reported on its own line, with what is expected, and the program exits with 1 after listing all of them. The settings in use are logged at start, with the database password hidden.

A run now stops with the reason instead of looping forever or reporting a broken archive as healthy: when the bucket answers 404 or another error for a block file, when `mina-missing-blocks-auditor` or `mina-archive-blocks` logs an error (for example an unreachable database), and when an imported block does not change what the auditor reports. `audit` exits with 1 when blocks are missing.
