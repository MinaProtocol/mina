Fix ledger sync for nodes whose saved ledger came from a fork that lost

When a node bootstraps, it syncs the network's ledger into the ledger it already has on disk. If that ledger held accounts the network's ledger doesn't, for example after the node ran on a fork that was later abandoned, the sync could never finish. Alternatively, the sync could report success while the node still treated some of the removed accounts as present, so its ledger later diverged from the network's. The sync now removes those accounts, so bootstrap completes with the correct ledger.
