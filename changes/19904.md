Record protocol versions in the block's proven protocol state

From this hard fork, each block records the protocol version that produced it and the version its producer proposes to upgrade to, if any, inside the protocol state that the block proof covers, rather than alongside it. A node relaying a block can no longer change or strip these versions, so they can be relied on when tracking which versions block producers are signalling. Precomputed blocks gain a `protocol_versions` field in `blockchain_state`; the existing top-level `protocol_version` and `proposed_protocol_version` fields are unchanged.
