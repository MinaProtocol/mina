Add `--precomputed-blocks-dir DIR`, which writes each precomputed block to its own file named `<network>-<height>-<state-hash>.json`. That is the name the precomputed block bucket gives its objects, so the directory can be uploaded to that bucket unchanged, and any tool that already reads the bucket reads the directory as it is. Each block is written under a temporary name and renamed into place, so a reader never sees a block that is only half written. The directory must exist; the daemon refuses to start if it does not.

Precomputed blocks are now written by a background job rather than by the block handler, so a slow disk delays the dump instead of delaying block processing. Blocks reach several megabytes, and until now the daemon stopped for the length of each write. If the writer falls more than 16 blocks behind, the oldest queued blocks are dropped and each drop is logged as an error that names the block, so a gap in the dump is visible in the log.

`--precomputed-blocks-file` is deprecated. It appends every block to one file, which grows without limit, which nothing rotates, and in which finding one block means reading the whole file. It keeps working, and the daemon logs a warning when it is used.
