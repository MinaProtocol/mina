Allow delegating to the empty address, so an account can stop staking

Sending a stake delegation to the empty public key is no longer rejected. An account delegated to the empty address has no stake and cannot be selected to produce blocks, which gives delegators a way to opt out of staking without moving their funds. This is the first part of the unstaking work described in MIP 35.

Newly created accounts now start with no delegate instead of delegating to themselves, so an account does not stake until it delegates. The `delegate` field returned by GraphQL can now be null for an account that has never delegated.

The same rule applies to genesis ledger configs: an account whose `delegate` field is omitted or null no longer delegates to itself and does not stake. Ledger configs written as JSON must now name a delegate for every account that should stake, which for a block producer is its own public key. A daemon that loads a ledger in which no account delegates logs an error, since such a network cannot produce blocks. Ledgers distributed as tarballs are unaffected.
