Fix DHT peer discovery in the libp2p helper, which only ran once per process start

A node published its entry in the DHT membership directory exactly once, when the helper started, and never renewed it, so the entry expired after 48 hours and the node disappeared from the directory for the rest of its uptime. It also searched the directory for peers exactly once, so no peer that joined the network afterwards was ever discovered through the DHT. Both operations additionally ran a fixed 100ms after an asynchronous bootstrap, before the node knew enough of the network for either to reach the right peers.

The entry is now republished before it expires, and a node that has fallen below its low-water peer count searches the directory again, backing off from one second to five minutes until it recovers. Nodes that cannot be dialed from the outside, such as those behind NAT without port forwarding, benefit most: they were running at about two thirds of the peer count of a dialable node. Fixes #19385.
