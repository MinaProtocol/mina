Fix peer discovery over the DHT, which stopped working shortly after a node started

Mina nodes list themselves in a shared directory held by the peer-to-peer network, and read that directory to find nodes to connect to. Both halves were broken. A node listed itself once at startup and never renewed the entry, so it dropped out of the directory after 48 hours and stayed out for the rest of its uptime. It also read the directory once at startup, so nodes that joined later were never found. Both steps also ran a fraction of a second after startup, before the node knew enough of the network for either to work reliably.

A node now renews its own entry before it expires, and re-reads the directory whenever it is short of peers, retrying more slowly as it goes until its peer count recovers. Nodes that cannot be reached from the outside benefit most, since incoming connections were doing the work that discovery was not: on mainnet such a node was running at roughly two thirds of the peer count of a reachable one. If your node is behind NAT without a forwarded port, expect it to find more peers than before. Fixes #19385.
