Fix archive node memory growth during genesis ingestion and block processing

Starting an archive node against a large genesis ledger read every account into
memory before writing any of them, adding roughly 550 MiB on mainnet that stayed
held for the whole ingestion. Accounts are now read in batches, so
`--chunks-length` bounds the archive's own memory as well as the size of each
database transaction.

Separately, the archive node, Rosetta, and the hard-fork toolbox registered a new
prepared statement on their PostgreSQL connection for every query they ran, so a
long-lived connection's server-side memory grew without limit — one backend
reached 2 GB while ingesting the mainnet genesis ledger. Queries now reuse their
prepared statements, which also makes ingestion roughly twice as fast.
