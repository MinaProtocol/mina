Reduce VRF evaluator memory use for block producers with many delegators

The VRF evaluator subprocess now receives only the public key and balance of each account delegating to the block producer, instead of the full account. This cuts the evaluator's memory per delegator by about 4–5×, from roughly 0.7–0.8 KB to 0.16 KB. For a block producer with 100,000 delegators, that is around 16 MB instead of 66–83 MB. The epoch data the daemon sends to the evaluator at each epoch shrinks by a similar factor.
