Reduce memory use and start time on nodes that do not produce blocks

A daemon with no block production keys configured no longer starts a prover or a VRF evaluator, which together held around 1.5 GB and did no work on seed, archive, block feeder, RPC and Rosetta nodes. Such a node now runs only the daemon, a verifier and the libp2p helper, so monitoring that assumes a prover process is present — including Prometheus prover metrics — needs updating on those hosts.

Verification keys now ship with the release and are installed to `/var/lib/coda/verification_keys/<profile>/`, or can be pointed at with `--verification-keys-file`. A node with no key file computes them at start instead, which takes around 30 seconds and several gigabytes of memory. A key file that does not match the runtime configuration in use is never used to verify blocks: one named with `--verification-keys-file` stops the daemon with a configuration error, while the installed one is ignored with a warning so that a configuration overriding a proof constant still starts.
