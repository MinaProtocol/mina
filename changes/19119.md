Fix `mina advanced validate-transaction` always reporting failure on valid input

Even when every transaction verified, the command printed "Could not parse any transactions" and exited 1, so there was no way to tell a good batch from a bad one. It now prints "All transactions were valid" and exits 0 when the input is good. Reading from a terminal, it also no longer waits for a second Ctrl-D before finishing.

GraphQL introspection changes for the `token` argument on the `account` and `accountActions` queries: it now advertises the default MINA token id where it previously advertised `null`. The effective default is unchanged, but generated clients and typed schemas will see the new value.
