Fix Rosetta `/search/transactions` paging and `total_count`

`total_count` depended on the requested page: it counted only the transaction kinds present in that page, and a page past the end reported 0. Paging with `offset` past the user commands also skipped every internal and zkApp command, and a response listed internal commands before user commands while pages were cut user commands first. `total_count` is now the size of the whole result on every page, a response lists user, then internal, then zkApp commands, and pages add up to the whole result.
