Make delegation_verify check that a submission's block_hash is the hash of its block

The stateless verifier of the delegation program verified the block attached to a submission, but not that this block was the one named by the submission's `block_hash`. A valid block could be verified and reported under the hash of another block. Blocks are loaded once per hash, so the first submission naming a hash also decided the block that every other submission naming that hash was verified with.

The verifier now computes the hash of the block data the way the uptime service backend does: the Base58Check encoding, with version byte `0x10`, of the Blake2b-256 digest of the raw block bytes. It rejects the submission when this hash is not its `block_hash`. The check runs before the block proof is verified, and `--no-checks` skips it like the other checks. Submissions stored by the uptime service backend are unaffected. Input that uses another value as `block_hash`, for example the state hash of the block, is now rejected.
