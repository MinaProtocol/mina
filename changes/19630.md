Replace the missing-blocks guardian script with an OCaml app built on the auditor

`mina-missing-blocks-guardian` is now an executable with the same `audit`,
`single-run` and `daemon` subcommands and the same environment variables, so
existing archive deployments do not need to change. It runs the audit of
`mina-missing-blocks-auditor` in process, through the auditor's library, instead
of running the auditor binary. `mina-missing-blocks-auditor` is still installed,
with the same `--archive-uri` flag, log lines and exit-code bits.

The guardian no longer saves a bucket's "not found" page as a block file. A
download that returns 404, is refused, is redirected, or is not a valid block
is now reported with the URL and the reason, instead of failing later with a
parse error that named neither. A block the archive
accepts but does not store, and an archive that does not reach back to a
genesis or hard-fork block, are also reported instead of making the guardian
retry the same block forever. The audit names which one is missing: the
genesis block, or the first block after a hard fork. The audit no longer fails with a decoding error
on an archive whose earliest block is not the genesis block.

A block the guardian cannot fetch or store no longer hides the rest. It sets
that branch aside, repairs the branches it can, and lists what is still open,
so one unreachable block at the bottom of a truncated archive no longer stops
the gaps above it from being filled. `single-run` exits non-zero whenever a gap
is left.

New optional flags let you set the block source, network, poll interval and
retry behaviour on the command line, cap one repair pass with `--max-blocks`,
and check that the missing blocks can be downloaded without writing anything
with `--dry-run`. Use `--min-height` on an archive that starts at a hard fork
or was restored from a truncated dump: it declares where the chain is meant to
start, so the earliest block counts as the bottom of the archive instead of a
missing block, and `audit` on a healthy archive of that shape returns success.

Every guardian subcommand now exits 0 when there is nothing wrong and 1 when
there is; the script's `audit` subcommand always returned 0. Each problem is
logged as an error line naming it. The auditor keeps its bit mask, and accepts
the same optional `--min-height`.

The audit itself, in both tools, now also reports an archive holding no
canonical block at all, under the auditor's missing-blocks bit; before, the
auditor stopped with exit code 1 on it. On an archive that starts at a hard
fork, a canonical chain that really is short is now reported, and a healthy one
is not — it used to be measured as if every chain began at height 1, so a
healthy forked archive was always reported as incomplete. An empty archive is
reported even when `--min-height` is given.
