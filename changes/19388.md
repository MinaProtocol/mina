Make the o1Labs deb-mirror authoritative for EOL bullseye image builds

Bullseye left LTS on 2026-08-31 and `deb.debian.org` stopped re-signing `bullseye-security`; its Release now carries a `Valid-Until` in the past and will never be refreshed, so every bullseye Docker image build failed in its first `apt-get update` with `E: Release file ... is expired` (exit 100). The deb-mirror was already an apt source on bullseye but only alongside the distro's own `sources.list`, so the expired upstream pocket still poisoned the run.

`configure-apt-proxy.sh` gains a per-codename `MIRROR_AUTHORITATIVE` flag (`bullseye=1`, `focal=0`). When set, apt probes the mirror using only `mirror-debian.list`; on success the distro's own sources are emptied so the mirror is the sole OS package source, and on failure the mirror list is dropped, upstream is restored with `Acquire::Check-Valid-Until` disabled, and the Debian archives are sent `DIRECT` past apt-cacher-ng (which shares a host with the mirror). `focal` keeps its existing additive behaviour.

CI builds the daemon, auto-hardfork and archive stages `FROM` the published `mina-base` (`scripts/docker/build.sh --base-image`) and skips `1-base-deps`, so those three stages now re-run `configure-apt-proxy.sh` themselves before their first `apt-get update`; the script is idempotent when `1-base-deps` already ran it.
