Fetch the scan state in verifiable pieces when bootstrapping, and hold it in less memory

A node joining the network had to fetch the staged ledger's scan state from a single peer in one response, and could not check any of it until all of it had arrived. A transfer that failed part-way cost the whole of it, and a peer that sent something wrong was only found out at the end.

The scan state is now fetched piece by piece, from as many peers as are available, with each piece checked against the block it belongs to as it arrives. A piece that fails to arrive is retried on its own. The structure is also held more compactly: on a test network carrying a full scan state, nodes used about half the memory they did before.

Bootstrapping on a fast local network is slightly slower than before, because fetching in pieces costs extra round trips. On a real network, where transfers can fail, retrying one piece rather than the whole scan state is what makes bootstrapping practical as the scan state grows.

This changes how nodes talk to each other and how the scan state is stored, so it is not compatible with earlier versions: nodes must upgrade together, and an existing node rebuilds its frontier database on first start.
