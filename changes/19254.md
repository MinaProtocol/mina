Speed up block production when snark work is scarce

A block producer applied candidate transactions up to the full transaction capacity before checking how much completed snark work was available to include them, so when work was scarce it applied transactions it then had to discard. It now applies only as many as the available work can pay for. On a network with little snark work this removes most of the time spent building each block; where work is plentiful nothing changes, and the transactions included in a block are unaffected in either case.
