Fix GraphQL account responses that were not valid JSON for some token symbols and zkApp URIs

A token symbol or zkApp URI can be any bytes, and the daemon wrote them unchanged into GraphQL responses, so a value that is not valid UTF-8 (Mainnet has one, set in block 565083) made the response invalid JSON. `tokenSymbol` and `zkappUri` now return each such byte as the character U+00XX; valid UTF-8 values are not changed. The new `tokenSymbolBytes` and `zkappUriBytes` fields give the exact value: `hex` holds the bytes, and `utf8` holds them as text or is null when they are not valid UTF-8.
