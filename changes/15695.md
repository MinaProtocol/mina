The replayer can now confirm that it reconstructs the expected epoch ledgers. Add
the optional field `target_epoch_ledger_hashes` to the replayer input file. It
holds a pair of ledger hashes: the staking epoch ledger hash and the next epoch
ledger hash. While the replayer applies transactions, it compares each ledger
root with these two hashes. The replayer checkpoint file then reports
`has_seen_staking_epoch_ledger_hash` and `has_seen_next_epoch_ledger_hash`, each
as a pair of a boolean and the global slot at which the match occurred. The
field is optional, and the replayer behaviour does not change when you do not
supply it.
