Add an opt-in memory-mapped cache for proving keys

Proving keys can now be loaded from a memory-mapped file rather than being
decoded into the heap, which lets the operating system reclaim those pages
under memory pressure instead of holding them resident for the life of the
process. This mainly benefits block producers and SNARK workers, which hold
several large proving keys at once.

The cache is off by default; set `MINA_USE_MMAP_CACHE=1` to enable it. It uses
a different on-disk format from the existing cache, so keys written by one are
not readable by the other and the key cache is rebuilt the first time a node
runs with the setting changed.
