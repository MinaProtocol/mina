Add a memory-mapped cache for proving keys

Proving keys can now be loaded from a memory-mapped file rather than being
decoded into the heap, which lets the operating system reclaim those pages
under memory pressure instead of holding them resident for the life of the
process, and lets processes on the same host share them. This mainly benefits
block producers and SNARK workers, which hold several large proving keys at
once.

The cache is on by default; set `MINA_USE_MMAP_CACHE=0` to disable it. It uses
its own on-disk format, in files named with a `.mmap` suffix beside the
existing keys. On first start, keys already present in the existing format are
converted rather than regenerated, and nodes in either mode can share a cache
directory. To share pages between processes and containers, the cache
directory must be on a disk-backed filesystem that they all mount.
