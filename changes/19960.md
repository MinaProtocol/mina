Remove the transaction version from the `setVerificationKey` permission

The `setVerificationKey` permission is now a plain authorisation, like every other permission, in transactions, GraphQL, and runtime configs. Runtime configs that give it as an object with `auth` and `txn_version` are still accepted, and the version is ignored. Archive nodes must apply the upgrade script, which drops the stored permission version. Precomputed blocks from before the hard fork still load, and their transactions keep their original hashes. zkApp transactions made for the previous network format are not valid after the hard fork, including ones that don't set permissions, so they must be rebuilt and signed again.
