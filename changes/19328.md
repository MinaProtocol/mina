- New `rosetta_client` library (`src/lib/rosetta_client/`): a thin HTTP client for
  a running Mina Rosetta server, with one function per Data API endpoint. Requests
  are built as the generated models in `src/lib/rosetta_models/`, so the field
  names, the required/optional split and the nesting come from the schema.

- New `rosetta-client` CLI: one subcommand per Rosetta Data endpoint, for
  debugging and for scripting against a running Rosetta server. It fills in the
  `network_identifier`, prints the response as JSON (`--compact` for one line),
  and exits non-zero with a short diagnostic on failure. See
  `src/app/rosetta/client/README.md`.

- The binary reads `MINA_ROSETTA_URI`, `MINA_ROSETTA_BLOCKCHAIN` and
  `MINA_ROSETTA_NETWORK`, so an operator who works against one server can export
  them once instead of repeating `--rosetta-uri`, `--blockchain` and `--network`
  on every call. A flag always wins over the matching environment variable, and a
  variable that is set but blank counts as unset.

- Error messages are short and human-readable: a Rosetta error envelope is
  rendered as `HTTP <code> from <url>: <message>`, a connection failure as
  `connection refused to <url>`. Raw OCaml exception text no longer reaches the
  terminal, an HTTP body is never written out verbatim, and a message is never
  split over several lines.

- `scripts/tests/rosetta-helper.sh` no longer builds JSON request bodies in bash:
  every call goes through `rosetta-client`. The `curl` calls it replaces had no
  request timeout, which could hang a CI job; the replacement defaults to 300 s.

- The binary ships in the `mina-rosetta` Debian package as
  `/usr/local/bin/rosetta-client`.
