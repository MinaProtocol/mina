Speed up block production by not hashing while checking candidate transactions

When building a block, a producer applies candidate transactions to a throwaway ledger to find out which ones are valid, then discards it. That ledger was still doing the full merkle hashing work for every account it touched, none of which was ever read. It no longer does, which makes checking each candidate several times cheaper and speeds up block creation, most noticeably on networks with large blocks. The transactions a block ends up containing are unchanged.
